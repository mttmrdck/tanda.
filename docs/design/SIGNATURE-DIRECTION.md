# Tanda signature direction

The latest user brief governs this phase: monochrome architecture, selective liquid-glass controls, preserved assistive monitoring behaviour. It replaces the earlier teal exploration. The blue supplied icon remains the existing brand asset; no new decorative colour is introduced.

## Three explored directions

| Direction | Composition and typography | Material/navigation | Density and interaction | Decision |
| --- | --- | --- | --- | --- |
| Architectural monochrome | Open identity dossier, divided operating strip, aligned event records, one tuned sans | Solid neutral rail, hairline boundaries, strong black/white actions | Highest scanability; fast state changes | Primary structure: best for everyday care decisions |
| Monochromatic Liquid Glass | Layered camera controls, floating contextual dock, subtle depth around identity | Frosted silver/charcoal chrome, inset highlights, restrained blur | Moderate density; tactile press, focused drawer movement | Adopt at navigation, identity and occasional overlays; avoid transparent event text |
| Editorial premium technology | Larger individual name, asymmetric review/communication layout, generous reading measure | Mostly opaque paper/graphite, sparse framed surfaces | Strong human focus; quieter operational signals | Adopt identity hierarchy and whitespace; reject oversized editorial titles/data |

Selected: **Care, in focus** — architectural monochrome with tactile glass chrome. The recognisable vocabulary is the identity dossier, four-part operating rule, margin-marked review timeline, frosted icon dock and solid decisions. The app remains a task surface, not a marketing page.

## Palette

Light: #F5F5F5 foundation, #FAFAFA surface, #171717 text/actions, #262626 hover, #666666 metadata. Dim: #0A0A0A foundation, #171717 surface, #262626 secondary, #F5F5F5 text/actions, #A3A3A3 metadata. Green, amber and red carry actual state, review and destructive meaning only. A 60/30/10 balance is compositional guidance, not fabricated pixel-area measurement.

## Resources actually inspected

- Local Frontend Design: distinctive subject-led composition, single-family type, removing decorative labels.
- Local Design System and token architecture: preserve the existing CSS/semantic-token pipeline; no second theme system.
- UI/UX Pro Max local search: used accessibility, target-size, motion and responsive guidance. Its sales-page recommendation and blue/green palette do not apply to the user's pinned app brief.
- Impeccable context and Operate/craft guidance: compact product hierarchy, native affordances, rendered critique. The context command found no PRODUCT.md; product truth is already explicit in README, architecture report and supplied briefs. No new product interview or inferred care claim was added.

## Reference analysis

[Apple materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials): material should distinguish controls/navigation from content while preserving legibility. Applied as bounded frosted chrome and solid reading surfaces; this is a CSS web interpretation, not Apple's native refraction renderer.

[Linear's interface refinement](https://linear.app/now/behind-the-latest-design-refresh): predictable action placement and reduced visual competition help a growing product stay coherent. Applied to consistent headers, contextual controls and ordered navigation; no interface was copied.

## Motion review

| Before | After | Why |
| --- | --- | --- |
| Wrapping mobile primary links plus secondary bar | One five-destination glass dock and focus-trapped full menu | Reduce competing navigation and preserve route access |
| Decorative tracked labels above every title | Title and relevant individual/source context only | Remove duplicated reading hierarchy |
| Identical emphasis on every event | Review-priority record gets a restrained margin marker; other records stay neutral | Draw attention to actual review work |
| Large inactive camera frame spanning the page | Bounded camera stage with source/privacy context beside it | Keep controls and camera state within useful reach |
| Colour-only visual changes | Text status, icon and brief opacity/colour transition | Communicate changes without implying detector confidence |

Preserve the existing skeleton route transition, CSS export fan, native keyboard semantics and reduced-motion behaviour. No perpetual faux-live motion or invented baseline progress.
